# Productivity Dashboard

[![Live Demo](https://img.shields.io/badge/🚀_Live_Demo-productivity--dash.seanford.io-blue?style=for-the-badge)](https://productivity-dash.seanford.io)

An all-in-one productivity dashboard designed as a practical exercise in full-stack web architecture, containerized deployment, and automated CI/CD pipelines.

 [**Features**](#features) • [**Tech Stack**](#tech-stack) • [**CI/CD Flow**](#cicd-flow) • [**Local Setup**](#local-development)

---

## Features

- **Habit Tracker:** Create and track daily habits.
- **Todo List:** Create, check off, and delete tasks.
- **Active App/Site Blocker Session Display:** View the actively running App/Site Blocker sessions along with a live time remaining display.
- **Authentication & Access Control:** Login via Github OAuth (with protected routing), or explore instantly using a read-only **Guest Demo Mode** that lets you try out the app without mutating the database.

- **Next.js** (App Router) & **TypeScript**
- **Tailwind CSS**

### Backend & Auth

- **PostgreSQL** via **NeonDB** and **Postgres.js**

### DevOps & Testing

- **Docker & Docker Compose**
- **AWS EC2 & ECR** (Automated container registry & hosting)
- **Vitest** (Unit testing)
- **GitHub Actions** (CI/CD pipeline for quality checks, automated testing, and automated deployment)
- **Husky & lint-staged** (Pre-commit and Pre-push hooks enforcing ESLint, Prettier, and TypeScript Compilation)

## CI/CD Flow

This application is fully containerized and deployed to AWS via a Github Actions pipeline.

```text
[ Developer Machine ]
   │
   ├── Husky: pre-commit ──> ESLint + Prettier
   └── Husky: pre-push   ──> tsc --noEmit
            │
            │ (Open Pull Request)
            ▼
[ GitHub PR Checks: quality-check.yml & test.yml ]
   ├── ESLint + Prettier
   ├── tsc --noEmit
   └── Vitest
            │
            │ (Merge PR into main)
            ▼
[ Build, Push, and Deploy: deploy.yml ]
   ├── 1. Authenticate with AWS
   ├── 2. Build & Push Production Docker Image to AWS ECR
   └── 3. SSH into AWS EC2
            │
            │ (Automated Deploy)
            ▼
[ AWS EC2 Target Host ]
   ├── Pull Latest Image from ECR
   └── Restart Container
```
   
**Amazon ECR (Elastic Container Registry):** Serves as the private registry storing versioned Docker images generated by CI runs.

**Amazon EC2:** Hosts the running Docker container inside a t3.micro instance and exposes it to web traffic.

## Local Development

### Prerequisites

Development Environment (Tested & Verified):

- **Node.js:** v26.4.0+ (Container runs `node:26.5.0-slim`)
- **pnpm:** v10.28.0+
- A **PostgreSQL** database connection string
- A **Github OAuth Application** Client ID and Secret

Optional:
- **Docker Engine:** v29.6.2+
- **Docker Compose:** v5.3.1+

### Option A: Standard Setup

1. Clone & Install

   ```bash
   git clone https://github.com/Lushtrii/productivity-dashboard.git
   cd productivity-dashboard
   pnpm install
   ```

2. Create a `.env.local` file in the root directory and fill in your credentials:

   ```
   DB_CONN_STRING="postgresql://user:password@endpoint.neon.tech/neondb?sslmode=require"
   AUTH_SECRET="your-auth-js-secret"
   AUTH_GITHUB_ID="your-github-oauth-client-id"
   AUTH_GITHUB_SECRET="your-github-oauth-client-secret"
   ```

3. Run Development Server
   ```
   pnpm dev
   ```

5. Open http://localhost:3000 in your browser.

### Option B: Running via Docker Compose

If you prefer not to manage local Node environments:

   1. Create a `.env.local` file with the required variables as shown above.

   2. Build and spin up the containerized app:
      ```
      docker compose up --build nextjs-dev
      ```
   3. Open http://localhost:3000 in your browser.
